# Security gates

Semgrep 1.179.0 scans the Java and TypeScript source using `p/java` and `p/typescript`. The registry rule sets may evolve; each run records the actual findings and scanner metadata. Trivy 0.75.0 checks Gradle/npm dependencies, including development dependencies, and scans all three built runtime images. Both Trivy gates fail on HIGH or CRITICAL CVEs without an ignore file. Gitleaks 8.30.1 scans the assignment path and workflow in Git history, including deleted material. It does not claim to audit unrelated students' submissions in the shared repository.

The original runtime dependency selection contained Spring MVC CVE-2026-47884 (CRITICAL). The Spring 6 line had no fixed release listed by the scan, so the application moved to Spring Boot 4.1.1 and Spring 7 rather than suppressing the finding. Tomcat 11.0.24 and Jackson 3.1.5 findings were then corrected with Tomcat 11.0.25 and Jackson 3.1.7. After these changes, all 15 tests and the frontend build passed, and the source dependency report contained zero HIGH/CRITICAL findings.

Runtime image results are separate from the source dependency report: they also include the operating-system and Java runtime packages. Refer to the pipeline's `capstone-image-security` artifact for the image reports and registry digests; do not treat a source-only scan as an image scan. Tool archives are pinned and checksum-verified by `scripts/install-tools.py`; the Gradle wrapper verifies its distribution checksum, and package versions are locked.

This is a temporary teaching application. Its CRUD API has no authentication and must stay on a local or controlled assignment network. Credentials are generated outside Git, injected through environment variables/Secrets, and excluded from reports. AWS keys are never supplied to GitHub Actions.

The first image gate also caught eight HIGH/CRITICAL findings in Debian 13 libexpat and libuuid packages in the initial distroless base, with no fixed Debian version listed. The runtime base was changed to the official Temurin 21 Alpine JRE, preserving UID 65532 and the runtime restrictions. This change is subjected to the same image gate; the failed run is retained as evidence that publication is blocked. All three image reports are collected before the job exits, even if one image fails.

The next run scanned both Temurin-based backend images and the frontend with zero HIGH/CRITICAL findings. That run was cancelled during the Kubernetes stage after the local startup tests exposed a Kafka DNS dependency problem; it is not described as a successful full pipeline. The subsequent chart and consumer retry changes passed the complete run [37586435056](https://github.com/vimalyad/devops-heros/actions/runs/37586435056), including kind deployment and cleanup.
